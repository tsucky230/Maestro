# 教訓抽出ワークフロー (/learn)

このワークフローは、プロジェクトの対話ログから「教訓」を抽出し、Maestroの知識ベース（`knowledge/`）に反映するためのインタラクティブなガイドです。

## 手順

1. **対象プロジェクトとログの特定**
    - ユーザーに「どのプロジェクトのログから抽出しますか？」と尋ねる。
    - 指定されたプロジェクトの `docs/projects/<project>/logs/` にある直近のファイル（5件程度）を**1から始まる番号付きリストで表示し、番号で選択できるようにする**。
    - ユーザーに処理対象のログファイル番号を選択させる。

2. **教訓タイプの選択**
    - ユーザーに「どのような種類の教訓として登録しますか？」と尋ねる。
        1. **トラブル事例 (Trouble Case)**: 失敗やバグの解決策（→ `knowledge/trouble-cases.md`）
        2. **成功/設計パターン (Pattern)**: うまくいった設計や実装パターン（→ `knowledge/patterns.md`）
        3. **チェックリスト (Checklist)**: 次回から確認すべき項目（→ `knowledge/checklists.md`）
        4. **その他**: 自由記述

3. **抽出とドラフト作成**
    - 選択されたログファイルを読み込む。
    - 選択されたタイプに対応する知識ファイル（例: `knowledge/trouble-cases.md`）を読み込む。
    - ログの内容から、知識ファイルのフォーマットに従って「新規エントリ」のドラフトを作成し、提示する。
    - **ポイント**: プロジェクト固有の事情（固有名詞など）を排除し、他のプロジェクトでも使える「汎用的な知見」に昇華させること。

4. **ユーザーレビューと保存**
    - 作成したドラフト（追記内容）をユーザーに提示し、「この内容で追記してよいですか？」と確認する。
    - 修正指示があれば反映する。
    - **Goサインが出たら**: 対象の `knowledge/` ファイルに追記保存する。
    - 完了報告をする。

---
> **Note**: このワークフローは対話的に進めます。一度にすべてを実行せず、ステップごとにユーザーの確認を取ってください。
