# 組み込みシステム開発 制約・チェックリスト集

> **使用方法**: 組み込みソフトウェアプロジェクトの場合、各工程で該当セクションを参照してください。
> SWP.1 の要求ヒアリング時に「逆質問テンプレート（§1）」を使い、HW制約を漏れなく収集してください。

## 2. 非機能要求テンプレート — 組み込み版（SWP.1）

要求仕様書の非機能要求セクションに以下のカテゴリを含める：

### 2.1 リソース制約

```markdown
### REQ-NF-RES: リソース制約

**要求**: ソフトウェアはHWリソース制約を遵守すること

**理由**: マイコンの物理的メモリ制限を超過するとシステム動作不能となるため

#### 仕様
- **SPEC-NF-RES-001**: ROM使用量 ≤ [上限値]KB（全体の[X]%以下を維持）
- **SPEC-NF-RES-002**: RAM使用量 ≤ [上限値]KB（ヒープ＋全タスクスタック合計）
- **SPEC-NF-RES-003**: EEPROM書き込み頻度 ≤ [回/日]（寿命[Y]年を保証）
- **SPEC-NF-RES-004**: CPU使用率 ≤ [X]%（ピーク時含む）
```

### 2.2 タイミング制約

```markdown
### REQ-NF-TIM: タイミング制約

**要求**: リアルタイム性を要する処理は指定デッドライン内に完了すること

**理由**: デッドラインを超過すると安全機能の喪失や通信断が発生するため

#### 仕様
- **SPEC-NF-TIM-001**: 制御周期タスクのWCET ≤ [X]ms
- **SPEC-NF-TIM-002**: 割込み応答時間 ≤ [X]μs
- **SPEC-NF-TIM-003**: 通信応答タイムアウト ≤ [X]ms
```

### 2.3 安全性

```markdown
### REQ-NF-SAF: 安全性

**要求**: 異常発生時にフェイルセーフ状態に遷移すること

**理由**: ハードウェアの物理的故障や異常が人身・機器の損害に繋がるため

#### 仕様
- **SPEC-NF-SAF-001**: WDTリセット発生時、安全な初期状態に復帰する
- **SPEC-NF-SAF-002**: 通信断検出後[X]ms以内にフェイルセーフ出力に切替える
- **SPEC-NF-SAF-003**: 電源電圧低下(LVD)検出時、不揮発データを退避して停止する
```

## 3. RTOS設計チェックリスト（SWP.2 / SWP.3）

### 3.1 優先度設計

- [ ] タスク優先度がデッドライン順（RMS/DMS）に基づいて設計されているか
- [ ] 優先度逆転防止策が導入されているか（優先度継承/シーリング）
- [ ] 全タスクの優先度一覧表が作成されているか
- [ ] 同一優先度のタスクが存在しないか（ラウンドロビンが意図的でない場合）

### 3.2 デッドロック防止

- [ ] 複数ミューテックスの取得順序が全タスクで統一されているか
- [ ] タイムアウト付きのロック取得が使用されているか（無限待ちの禁止）
- [ ] ネストしたロック取得が存在する場合、デッドロックフリーであることが証明されているか

### 3.3 スタック管理

- [ ] 各タスクのスタック使用量が見積もられているか（WCET時の最大深度）
- [ ] スタックオーバーフロー検出機能（MPUガード/スタックウォーターマーク）が有効か
- [ ] 割込みハンドラのスタック使用量が見積もられているか

### 3.4 WDT（ウォッチドッグタイマー）設計

- [ ] WDTクリアは単一タスクではなく「監視タスク方式」を採用しているか
- [ ] 全タスクの生存フラグを確認してからWDTをクリアする設計か
- [ ] 各タスクの処理時間 ＋ 通信待ち時間 ＜ WDTタイムアウト周期 であるか
- [ ] WDTリセット時のリカバリ手順が定義されているか
- [ ] 複数基板でのWDT起動順序によるデッドロックが発生しないか

### 3.5 割込み設計

- [ ] 割込み禁止時間の上限が定義されているか
- [ ] 割込みハンドラ内の処理が最小限か（後段処理はタスクに委譲）
- [ ] ネスト割込みの方針が決定されているか
- [ ] 割込み優先度とタスク優先度の関係が整理されているか

## 4. 複数CPU通信チェックリスト（SWP.2 / SWP.3）

### 4.1 起動シーケンス

- [ ] CPU間の起動順序と依存関係が定義されているか
- [ ] 初期化完了の相互通知（Ready信号）が設計されているか
- [ ] タイムアウトによるデッドロック回避が実装されているか（互いに待ち合わない）
- [ ] 片方が先に起動した場合の待機動作が定義されているか

### 4.2 通信プロトコルの堅牢性

- [ ] チェックサム/CRCによるデータ整合性確認があるか
- [ ] フロー制御（ACK/NAK、ハンドシェイク）が設計されているか
- [ ] 再送制御（リトライ回数上限、バックオフ）が設計されているか
- [ ] 疎結合設計か（片方のハング時に他方が引きずられないか）

### 4.3 状態同期

- [ ] 定期的なハートビート/生存確認が設計されているか
- [ ] ハートビートタイムアウト時のリカバリ手順が定義されているか
- [ ] 状態不一致（メイン側「通信中」、通信側「エラー終了」）の検出策があるか
- [ ] ステートマシン図で全CPU間の状態遷移が整理されているか

### 4.4 電力モード同期

- [ ] 一方がSleepに入る際、他方の通信待ちを解除する手順があるか
- [ ] Wake-upトリガー（割込み/イベント）が同期されているか

## 5. 組み込みロギング設計指針（SWP.3）

### 5.1 設計原則

組み込みではメモリ/ストレージ制約が厳しいため、「死因特定に必要な最小データ」に絞る。

| 原則 | 説明 |
|------|------|
| リングバッファ | 最新N件を保持。古いログは上書き |
| ブラックボックス保存 | WDTリセット/例外発生時のみ不揮発領域に退避 |
| レベル別フィルタ | Error/Warning/Info/Debug。本番はError+Warningのみ |
| 動的レベル変更 | デバッグ時のみ詳細ログを有効化できる構造にする |
| プローブ効果の最小化 | ログ処理自体がタイミングを変えないよう低優先度で実行 |

### 5.2 最小構成ログ定義（例: 保存容量 ≤ 1KB）

異常発生時にFlash/EEPROMに退避する最小ログ項目：

| 項目 | サイズ(byte) | 用途 |
|------|-------------|------|
| タイムスタンプ | 4 | 発生時刻（RTCまたはティックカウンタ） |
| リセット要因 | 1 | WDT/LVD/例外/外部リセット等 |
| プログラムカウンタ(PC) | 4 | 停止位置の特定 |
| スタックポインタ(SP) | 4 | スタック状態の確認 |
| 現在タスクID | 1 | 障害発生タスクの特定 |
| CPU使用率 | 1 | 過負荷状態の確認 |
| 電源電圧(ADC値) | 2 | LVD関連障害の判断 |
| 直近通信エラーコード | 2 | 通信障害の判断 |
| WDTクリア履歴(直近5回) | 5 | タスクハング箇所の絞り込み |
| ヒープ残量 | 2 | メモリ枯渇の判断 |
| 予約 | 6 | 将来拡張用 |
| **合計** | **32** | — |

### 5.3 通信統計カウンタ

動的テスト・運用監視用に以下の統計カウンタを通信ドライバ層に設置する：

| カウンタ | 説明 |
|---------|------|
| 送信試行回数 | 一定期間内の総送信回数 |
| 送信成功回数 | ACK受信成功回数 |
| 再送回数 | リトライが発生した回数 |
| エラー種別カウンタ | CRCエラー/タイムアウト/NAK/バッファオーバーラン |
| 再送レイテンシ(最大/平均) | 初回送信〜成功までの時間 |

**再送率** = 再送回数 ÷ 送信試行回数 × 100（定期出力推奨）

## 6. テストフェーズ別観点マトリクス（SWP.4 / SWP.5 / SWP.6）

### 6.1 導出元 × フェーズ マトリクス

| 導出元 | 単体テスト (SWP.4) | 結合テスト (SWP.5) | 総合テスト (SWP.6) |
|--------|-------------------|-------------------|-------------------|
| **利用機能** | 関数単位の正常/異常/境界値 | 通信再送ロジックの妥当性 | ユーザー操作応答時間 |
| **HW部品** | 型オーバーフロー、メモリリーク | EEPROM書き込み頻度、消費電流 | 温度/ノイズ環境下の動作 |
| **RTOS** | スタック消費量の確認 | タスク間デッドロック検証 | WDT挙動、低電力モード遷移 |
| **通信I/F** | プロトコル単体（送受信バッファ） | 通信断/短絡時フェイルセーフ | 長時間連続通信の安定性 |
| **電源** | LVD検出ロジックの単体テスト | バッテリー残量→スロットリング連携 | バッテリー枯渇までの連続動作 |

### 6.2 工程別の重点確認項目

#### 単体テスト（SWP.4）で必ず確認

- [ ] 変数の型安全性（暗黙型変換、符号不一致、レジスタ幅超過演算がないか）
- [ ] メモリリーク（malloc/free対応、例外パスでの解放漏れ）
- [ ] リソースリーク（ファイル、セマフォ、通信バッファの未解放）
- [ ] スタック消費量の計測（静的解析 or ウォーターマーク）
- [ ] 境界値（0、1、MAX、EEPROM寿命回数-1/回数/回数+1）

#### 結合テスト（SWP.5）で必ず確認

- [ ] タスク間通信のタイミング検証（送受信の順序・遅延）
- [ ] 共有リソースの競合テスト（ミューテックス/セマフォ）
- [ ] 通信異常注入テスト（断線、短絡、ノイズ、タイムアウト）
- [ ] 起動シーケンスの順序テスト（CPU間の起動順入れ替え）
- [ ] 通信統計カウンタの妥当性確認（再送率の評価）

#### 適格性確認テスト（SWP.6）で必ず確認

- [ ] WDTリセット→復帰の動作確認
- [ ] 低電力モード遷移→復帰の動作確認
- [ ] EEPROM書き込み寿命シミュレーション（加速試験）
- [ ] 長時間連続動作テスト（メモリ枯渇/リソース枯渇が起きないか）
- [ ] 電源電圧低下(LVD)時のデータ退避動作確認
- [ ] 消費電流計測（バッテリー寿命の妥当性確認）

## 7. バッテリー駆動機器チェックリスト（SWP.2 / SWP.3）

### 7.1 消費電力の最適化

- [ ] アイドル状態での低電力モード（Deep Sleep等）への遷移が設計されているか
- [ ] 周辺ペリフェラル（ADC, 通信I/F等）の未使用時クロック遮断が設計されているか
- [ ] 高精度RTCを活用した間欠動作の管理が設計されているか
- [ ] 低電力モード移行前に全GPIOの状態が定義されているか（フローティングピンの排除）

### 7.2 バッテリー保護と安全性

- [ ] 充放電経路（トリクル充電等）の制御設計があるか
- [ ] 低電圧(LVD)検出時の安全シャットダウン手順が定義されているか
- [ ] 異常発熱/過電流時の緊急停止シーケンスが定義されているか
- [ ] バッテリー劣化時のパフォーマンス制限（スロットリング）が設計されているか

### 7.3 状態監視

- [ ] 残量計測アルゴリズム（クーロンカウンタ/電圧換算）が選定されているか
- [ ] 残量しきい値ごとのユーザー通知が定義されているか

## 8. 低電力モード移行 コードレビュー基準（SWP.4）

コードレビュー時に以下を検証する：

| # | チェック項目 | 対象 |
|---|------------|------|
| 1 | **ペリフェラル遮断**: 遷移前にADC、UART、タイマー等のクロック供給が停止されているか | 全言語 |
| 2 | **GPIO状態**: 非接続ピンがフローティングにならず、プルアップ/ダウンでリーク電流防止されているか | 全言語 |
| 3 | **復帰トリガー**: 復帰に必要な外部割込みやRTCが正しく有効化されているか | 全言語 |
| 4 | **RAM保持**: Sleep中にRAM内容を保持する必要がある場合、リテンション設定が有効か | 全言語 |
| 5 | **通知抑制**: 移行中に不要なAPI呼び出しや通知処理が抑制されているか | 全言語 |
| 6 | **復帰後の再初期化**: Sleep解除後にペリフェラルが正しく再初期化されているか | 全言語 |
